# sv_lint rules

The rules `sv_lint.py` checks, each with its source. Scope: the RTL
(`rtl-systemverilog/`), the checkers (`sva/`) and the testbenches (`tb/`),
tracked `.sv` / `.v` files only. `rtl-verilog/` is generated by sv2v and is not
linted. The linter only reports; it never rewrites a file. RTL findings are for
the designer to act on.

Run from `verif_automation/`:

| Command | What it does |
|---|---|
| `make lint` | every rule; fails on any error |
| `make lint_report` | the same, never failing - for reading the backlog |
| `make lint RULES=C1,S1` | only these rules |
| `make lint FILES=sva/protect` | only these files or folders, written from the repository root |
| `make lint_evidence` | save the full report as `evidence/lint/<date>_lint.txt` |

Accepted exceptions go in `exemptions.txt`, one per line: rule, path glob and
the reason. A line without a reason stops the run.

## Rules

| ID | Level | Rule | Source |
|---|---|---|---|
| H1 | error | The file opens with a header block containing `# Filename:`, `# File Description:` and `# Global variables:` lines. Presence only; what Global variables lists is not checked. | coding standard |
| H2 | error | The header's Filename names this file. | coding standard |
| H3 | error | The file ends with `` `default_nettype wire ``. | coding standard |
| C1 | error | Every `always_*` / `always` / `initial` / `final` block and every task and function has a Purpose block. A block that spans lines carries it inside, as the first thing after its declaration line; above the block no longer counts. A single-statement `always` / `initial` with no `begin` carries a Purpose block or a `//` comment above it; a run of them, with the declarations of the signals they drive, may share one comment. | rulebook §2 |
| S1 | error | An `if` or `else` whose statement is on its own line uses `begin` / `end`. A one-line `if` / `else` (statement on the same line) needs none. | coding standard |
| S2 | error | A blank line after every line that opens a block: a multi-line `begin`, the module header, a `task` / `function` / `property` / `sequence` declaration. When the block starts with its Purpose block, a blank line follows that too. A comment line does not count as blank. | coding standard |
| S3 | error | A blank line before every line that closes a block: `end`, `endmodule`, `endtask`, `endfunction`, `endproperty`, `endsequence`. A comment line does not count as blank. | coding standard |
| S4 | warning | The module body sits at the indentation of `module` / `endmodule`. Reported once per module. | rulebook §2 |
| K1 | error | Parameters and localparams are ALL CAPS. | rulebook §2 |
| N1 | error | In checkers, assertions are labelled `a_`, covers `c_`, named properties `p_`; no unlabelled assertion or cover. | rulebook §6 |
| N2 | error | Every named property is asserted or covered, and `a_X` asserts `p_X`. | rulebook §6 |
| N3 | error | Every assertion has a cover in its own PAC group (the lines between two `////////` rule lines). Stems need not match; cover-only groups are fine. A group without a cover must say so in its Purpose block: that it shares a named cover, or why it has none. | rulebook §6 |
| N4 | error | An assertion reports through `sva_pkg::note_failure()`, with a message starting with its own label. | rulebook §6 |
| N5 | error | No `$error` / `$fatal` in a checker; no `$fatal` in a testbench. | rulebook §6, §7 |
| P1 | error | A property about reset (its antecedent tests `!rst_n`) has no `disable iff`. | rulebook §4 |
| P2 | error | No `===` / `!==` in a checker; `==` in properties. | rulebook §4 |
| P3 | error | No `$rose` / `$fell` on a multi-bit signal (judged where the argument is declared in the same file). | rulebook §4 |
| B1 | error | Every checker module is bound in `sva/bind_sva.sv`, and every bind names a checker that exists. | rulebook §1, §6 |

## Decided against

| Proposed rule | Why not |
|---|---|
| `$stable` / `$changed` must pair with `\|=>` | Dropped by JK. An antecedent holding `$past(...)` makes `\|->` correct. |
| No `1'b1 \|->` | Dropped by JK: a matter of preference. |
| `&counter` in a property flagged | Dropped by JK. |
| No block comment starting with "verilator" | Dropped by JK. The pragma itself (`/* verilator lint_off */`) is legitimate. |
| p / a / c must share a stem | Dropped: a group's covers are named for what they show, and some groups are cover-only. N3 checks the group instead. |
| No randomness in SystemVerilog testbenches (was T1) | Dropped by JK: a working rule while learning cocotb, not a project rule. |
| `WATCHDOG_NS` written from `CLK_PERIOD_NS` (was T2) | Dropped by JK: too restrictive. |

## The block layout

C1, S2 and S3 together give every block the same shape:

```
always_ff @(posedge clk) begin      task automatic tick(input int n);

    /*                                  /*
    Purpose:                            Purpose: advance n clocks.
    ---                                 */
    What the block does.
    */                                  repeat (n) @(posedge clk);

    if (a) begin                    endtask

        b <= 1'b0;

    end

end
```

That is a blank line after every block opener and before every block closer,
with the Purpose block first inside. One line (`if (a) b <= 1'b0;`,
`begin x; end`) needs none of it.

Checked against the code before the rule was fixed: modules, `always` /
`initial`, `begin` / `end`, tasks, functions and properties all fit it.
`case` / `endcase`, `fork` / `join` and `generate` / `endgenerate` are left
out: they are not `begin` / `end` blocks, and in the current code 13 of 18
`case` statements and every `fork` start straight into their items.

## Not yet checked

These need a SystemVerilog parser (pyslang) or judgement, and are not in the
linter yet:

- A property spanning two edges (`$past`, `$stable`, `$changed`, `|=>`) is
  guarded against a mid-cycle reset (`$past(rst_n)`, or an out-of-reset
  helper).
- DUT internals reach a checker through `dut_` ports, not hierarchical names.
- Testbench stimulus after `@(posedge clk)` is offset by `#(DRIVE_OFFSET_NS)`.
- A guard the RTL acts on at one edge is not read a clock late in the
  consequent (the pgood_gen_sva bug of Nov 2026).
- Judgement: a property that says how a signal moves enumerates every way it
  can move (reset, saturation, clear); a property is not subsumed by another;
  timing claims come in lower / upper-bound pairs.
